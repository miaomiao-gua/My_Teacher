# 桌宠：工作台里的小玩偶 + 换形象（2026-10-06）

上一版（`2026-10-04-desktop-pet-design.md`）做的是**桌面端**的一只透明小桌宠。
这一版解决两件学生直接提的事：

1. 「他应该是类似一个**小玩偶**，在你之前做的**界面的基础上**配合一些**演绎动作**」
   → 工作台（`/agent/app`）右下角常驻一只小玩偶，跟着上课节奏动。
2. 「加一个入口，可以**换另一个模型**（白-免费版）」
   → 小玩偶标题栏一个「换形象」，弹层列出扫到的所有模型。

## 东西都在哪

| 文件 | 干什么 |
| --- | --- |
| `web/static/js/pet_core.js` | **形象引擎**：运行时加载、取景、动作发现、参数演绎、事件→动作、换形象弹层 |
| `web/static/css/pet.css` | 角色骨架样式（`.pet-*`）与小玩偶外壳（`.au-pet`），**两个界面共用一份** |
| `web/static/js/pet_page.js` + `web/pet.html` | 独立小窗口 `/agent/pet`（点「放大」打开的整身版） |
| `web/static/js/agent_ui.js` → `mountPetDoll()` | 工作台里的小玩偶：可拖、可收起、滚轮缩放取景、换形象、放大 |
| `kernel/pet_models.py` | **扫盘**列出可用形象、记住学生选了哪个、按 id 安全地发模型文件 |
| `kernel/server.py` | `/agent/live2d/models`、`/agent/live2d/model/{id}/{path}`、`/agent/pet/model` |

一份引擎两处用，是为了不出现「大窗口里正常、小玩偶里跑偏」这种两套实现的烂账。

## 演绎动作的两条路（核心设计）

学生的模型分两类，动作能力完全不同，所以有两条路，**互不打架**：

- **A 有动作文件**（艾琳 14MB / hiyori 3MB / mao_pro / shizuku）：
  按组名关键词挑着播（idle / think / speak / listen / tap / flick…）。
  组名每个模型都不一样（`Idle`、`idle_01`、`FlickDown`、还有一个**空字符串组**），
  所以先精确匹配、再包含匹配，且更具体的名字排在前面（`FlickDown` 要在 `Flick` 前面）。
- **B 一个动作文件都没有**（白-免费版 12.5MB、Q版小熊貓）：
  **程序驱动参数**——呼吸（ParamBreath）、左右摇摆（ParamAngleX/Z）、眨眼、
  说话时嘴动（ParamMouthOpenY）、惊喜时瞪眼、开心时蹦两下（DOM transform）。
  写入时机在库的 `afterMotionUpdate` 钩子里（动作算完、物理之前），这是唯一正确的位置。

正在播动作文件时，参数一律不写（`suppressedUntil`）——否则两边抢同一批参数，动作会抖。

实测证据（真浏览器里读参数值）：
白-免费版 静止 `ParamMouthOpenY=0`，说话时在 `0.26~0.70` 之间来回；`ParamAngleX` 同步摆动。

## 取景：从「满屏鞋子」到「玩偶特写」

踩过的三件事，都写进了测试，防止改回去：

1. 用 `model.width/height` 当缩放基准 → 那是**当前帧的包围盒**，刚加载时是错的，
   算出来放大好几倍。**必须用 `internalModel.originalWidth/Height`（模型原始画布）**。
2. 自己算 `x/y` 定位 → 应该用 `anchor.set(0.5, 1)`（锚点放脚底），
   整身版就是「脚底贴地」，小玩偶版是「画布顶边贴住框顶，只露出上方 32%」。
   小玩偶**允许左右裁掉**（最多各 1/3）—— 玩偶特写本来就这样；宽度不放开就永远只能看到全身。
3. 换形象时复用同一块 `<canvas>` → **一个 canvas 只能有一个 WebGL 上下文**，
   上一块在 `app.destroy()` 之后已经废了，拿它再建 PIXI 必然失败（表现为「换完掉回备用形象」）。
   现在每次加载都换一块新画布。

## 换形象

- 清单是**扫盘**得到的（项目里 / 用户的 client/ / 桌面 / Open-LLM-VTuber），
  按「目录名 → 文件名 → 上级目录名」取一个有人话味道的显示名，跳过 `runtime`、`models` 这类空名字。
- id 用路径哈希兜底、**不随扫描顺序变** —— 它同时是「记住学生选择」的钥匙。
- 选择存在 `data/pet_model.json`（服务端），所以网页版、小玩偶、桌面版看到的是同一个形象。
- 弹层里每个模型标了「自带动作 / 程序演绎动作」和体积，学生自己就能挑。

## 其它踩坑

- `#stage` 里**只能放角色**：引擎会清掉自己上次生成的东西。一开始把聊天抽屉放在
  `#stage` 里面，结果一开角色，抽屉被清没了 ——「跟她说句话」点了没反应。
  现在引擎只删自己那两类节点（`.pet-body` / `.pet-bubble`），绝不动宿主里的其它东西。
- 小玩偶的位置只**在真的拖动过之后**才写 localStorage（点一下标题栏不算），
  否则会莫名其妙记住一个怪位置。
- 模型的留白每个都不一样，所以给了**滚轮缩放取景**（按模型分别记住）。

## 自检（都能一条命令跑）

```
node data/agent/_pet_core_tests.js          # 动作映射/动作表/组名挑选/待机参数（纯逻辑）
py -3.14 tests/test_pet_models.py           # 扫盘、id 稳定、防穿越、只读、记住选择
py -3.14 tests/test_pet_page.py --http      # 页面/路由/取景与演绎规则 + 打真服务
node data/agent/_cdp_doll.js                # 真浏览器：小玩偶、事件驱动、换形象、参数演绎
node data/agent/_cdp_pet.js                 # 真浏览器：独立窗口页（聊天、提醒、兜底形象）
py -3.14 tools/check_pet_http.py            # 接口级端到端（清单/取文件/换形象/防穿越）
```
